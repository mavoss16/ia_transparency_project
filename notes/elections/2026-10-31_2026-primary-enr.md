# 2026-10-31 — 2026 primary from ENR, manual primary downloads

Part of Phase 1 of the [electoral history plan](2026-10-30_legislator-electoral-history-plan.md).

## Manual downloads

The user downloaded files by hand from sos.iowa.gov (R gets 403 there) into `data/elections/raw/Manual Primary Downloads/`:

| File | Contents |
|---|---|
| `2022 Primary/{county}.xls` (99) | Per-county precinct results. All are SpreadsheetML (`<?xml`, BOM first) despite the `.xls` name; the `contest_sheets` parser reads them once renamed `.xml` (Adair and Polk tested). |
| `2024_primary_county.xls` | Statewide SpreadsheetML, one sheet per contest, **one row per county** (not precinct). |
| `2026_primary_county.xlsx` | Statewide `.xlsx`, same layout, one row per county. |

County rows are enough for the race table, which only needs race totals. The 2024 county file matches the 98 ENR precinct files exactly for all 583 candidates outside Black Hawk, so it is the source for Black Hawk (ENR returns 404 for that county's 2024 primary file).

## 2026 primary from ENR

`download_results(2026, "primary")` listed 99 counties but every `reports/detailxls.zip` returned 404. The county's `electionsettings.json` has `"detailxlsfilesize":"-"`: ENR generated no Excel report for this election, only `detailxml.zip` (and `detail.txt`). That zip holds `detail.xml`, ENR's own XML format, not SpreadsheetML.

Changes:

- `download/election_results.R`: `download_enr()` tries `detailxls.zip`, then `detailxml.zip`; `sniff_format()` accepts `<ElectionResult>` as `xml`; `fetch_bytes(quiet_404 = TRUE)` keeps the expected 404 quiet.
- `legislative_results/parsers.R`: new layout `clarity_xml` (`read_clarity_xml()`), chosen when a `.xml` file starts with `<ElectionResult>`. Sums Election Day + Absentee per precinct; maps party codes (REP, DEM, LIB, IND) to the names other layouts print.

Result: 99 counties in `precinct_results/2026_primary/`, 9,972 legislative rows, 100 House and 25 Senate districts for each party. Against the statewide county file, 491 of 498 candidate totals match. The other seven:

- Six are labeling: the county file splits some write-ins by name ("Blank", "BLANK", "Tommy Hexter") that the precinct files count as "Write-in"; the sums agree (SD 25 Rep, SD 43 Rep, HD 53 Dem).
- HD 95 Dem: Louisa's file has a named choice "Carrie Trevino" (21 votes, no party attribute) that the county file doesn't count at all. Open in `ROADMAP.md`.

## 2025 specials added

Another session entered the five 2025 legislative specials in `data/elections/processed/legislative_results_special.csv` (county rows, checked against the certified canvasses; sources in `data/elections/raw/special_results/sources.csv`).

- `02`: `read_specials()` binds them to the precinct rows as `type = "special"`, county-level, keeping each special's own date and canvass URL (`election_date`, `source_url`). Race key is unchanged, so a second special for the same seat in one year would need `election_date` added to it.
- `03`: special winners count as seat matches (any general or special from 2022 on), and `race_counties()` includes specials. A special's winner is incumbent in later elections until the seat's next general.
- Result: 3,744 race rows; 786 matches (none to review). All five winners (Zimmer, Watkins, Ramirez, Drey, Larson) match their `people_id` and are incumbents in the 2026 primary, which closes the SD 35 gap. The one 91st GA member with no matched win is Renee Hardman (SD 16), probably a special not in the CSV.
