## Anti-Patterns Verdict

**LLM assessment:** Does not read as AI-made. Restrained palette, serif headings used sparingly, no gradients, no hero-metric template (the stat tiles are flat, labelled counts, not a hero). The one family-resemblance risk is the row of five equal stat tiles, which is the closest thing to a generic dashboard; it is earned here because the five numbers are the content.

**Deterministic scan (CLI, 3 files):** 1 finding, a false positive — `numbered-section-markers` on the archive, triggered by the count columns (10, 11, 12) of the data table.

**Browser detector (injected on all three pages):** `cramped-padding` on the Bootstrap nav-tabs `<ul>` (week page) — false positive, standard tab design. `line-length ~144 chars` on home — the weekly card's stale note ("No bill has reached a new stage since…", 98 chars on one line). Not prose, but it corroborates that the note is carrying too much. Archive: clean.

## Overall Impression

The weekly summary does what it set out to: a calm, factual answer to "what did the Legislature do this week," with the counting rule stated and the stale state handled. Its weakest layer is the R-generated table, which still looks like reactable's defaults rather than the site, and a status vocabulary that stops being true once resolutions and vetoes enter it. The single biggest opportunity: make the table and pills speak the site's design language, so an event ("passed committee this week") never looks like a state ("currently in committee").

## What's Working

- **Honest framing of time.** The stale note, "data through", and gap rows ("No recorded actions · Jul 20 – Sep 27") stop an out-of-session visitor from reading May as now — exactly the trust-through-restraint principle.
- **Connections, not collections.** Rows are bill groups: HF 2801 + HSB 785 + SF 2508 appear together, so the study bill → committee bill → companion chain is visible without explanation.
- **Progressive disclosure.** Counts → eight rows → full week → per-day tabs → per-row actions. Each layer is optional.

## Priority Issues

**[P1] "Awaiting Governor: 34" is wrong (home, adjacent to the weekly card)**
- Why it matters: only 11 of the 34 can be waiting on the Governor. 14 are adopted concurrent resolutions (added by the 2026-10-24 resolution fix), 2 joint resolutions (go to voters), 7 vetoed. A headline number that's 68% wrong undercuts the whole site's credibility.
- Fix: the status scale has no terminal state for resolutions or vetoes. Add "Adopted" (resolutions) and "Vetoed" as terminal statuses, or at minimum count only HF/SF bills with no veto in "Awaiting Governor". Also flag known LegiScan lag (HF 2801 signed Oct 2 per legis.iowa.gov).
- Suggested command: /impeccable clarify (copy) after a data fix

**[P1] Event pills and status pills are indistinguishable**
- Why it matters: "This week" (what happened) and "Status now" (where it stands) render as the same amber pill, with different casing ("Passed committee" vs "Passed One Chamber"). A newcomer can't tell an event from a state, and busy weeks become a wall of identical amber.
- Fix: keep filled pills for current status only; render this-period events as plain text or outline chips, showing the furthest event first ("Passed House" + "2 earlier steps"). Sentence case for all status labels.
- Suggested command: /impeccable distill

**[P1] Reactable keyboard focus is invisible or faint (WCAG 2.4.7)**
- Why it matters: sortable column headers receive focus with a 0px outline and no shadow; the row expander uses a 0.67px browser ring and is a 16×22px target.
- Fix: one shared reactable theme with `:focus-visible` outlines (2px, site ink/blue, offset) on headers, expander, page buttons and search; expander hit area ≥ 32px.
- Suggested command: /impeccable harden

**[P2] Reactable doesn't match the design system (sitewide)**
- Why it matters: cool #e6e6e6 2px header rule vs the site's warm #e4e2da; 3px-radius search box and page buttons vs 8px site buttons; bold ink headers vs the muted 0.78rem headers of the archive table; default pagination. The tables read as an embedded third-party widget — the "R-generated tables don't match" problem, and it applies to legislator_table() too.
- Fix: an `ia_reactable_theme()` in R/ui_helpers.R (reactableTheme: borderColor, headerStyle, searchInputStyle, pageButton styles, highlightColor = page tint) used by every reactable; align gt_theme_ia() header style with it.
- Suggested command: /impeccable extract

**[P2] Furthest-stage ordering lets resolutions lead the week**
- Why it matters: Feb 16 opens with HR 106 ("Urging the members of Congress…") above SF 2201 (school funding passing the House). Resolutions move fast, so they top every week. Hierarchy over volume.
- Fix: neutral tie-break using the existing salience bill class: substantive before resolution/commemorative at the same stage. Defensible, not editorial.
- Suggested command: /impeccable layout
